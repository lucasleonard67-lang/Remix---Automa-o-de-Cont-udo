## 0. Como o motor monta o input (vale para todo modelo Replicate) — CONFIRMADO

- O catálogo é DADO: `video_models` tem `capability`, `model_id`, `provider`, `cost`, `limits`, `input_template`, `required_inputs`, `tier`, `experience[]`, `label`, `notes` (VC:107-123; colunas do hub em SI:853-857).
- `resolveModel(capability, override, provider)` pega a linha ativa (override ou `is_primary`); override inativo cai no primário com aviso (VC:226-256).
- `renderInputTemplate(template, vars)` só substitui `{{prompt}} {{negative_prompt}} {{text}} {{keyframe_url}} {{audio_url}} {{video_url}} {{reference_urls}} {{reference_url}} {{duration_int}} {{duration_ms}} {{resolution}} {{voice_id}} {{language_boost}} {{bitrate}} {{language_code}} {{avatar_id}}` (VC:10-16, 126-147, 330-402). Placeholder sem valor → campo some. Formas `$list`, `$map`, `$when`.
- `missingRequiredInputs` compara com `required_inputs` antes de pagar (VC:413-418).
- Duração: `resolveDuration` (enum fechado sobe para o menor bloco ≥ fala; faixa contínua arredonda para cima e prende; `duration_from:'audio'` não manda) (VC:298-311). Resolução: `fitResolution`/`sceneResolution`, padrão 720p (VC:79-105; DA:290-292).
- Custo: `estimateCostUsd` por `unit` e `by_resolution` (VC:436-451). Replicate não expõe preço por API — tudo é estimativa humana (VC:429-435).
- **Nenhum lugar lê `video_models.notes` nem `input_template` para explicar à pessoa o que escrever**: a tela só lê `cost`, `limits`, `is_primary`, `required_inputs`, `label`, `provider`, `tier`, `capability` (`src/hooks/use-video-models.ts:116-127`); a frase do modelo vem de um dicionário fixo no front (MN:10-31, usado em `src/lib/generation-gate.ts:410`).

## 4. Respostas diretas

**(a) Existe hoje uma "receita por modelo" (como escrever para ele) que a tela ou o Claude possam ler?**
- **Não como estrutura.** O que existe:
  - `video_models.input_template` + `required_inputs` + `limits` (VC:107-123): dizem **quais campos** e **limites** o modelo recebe — não dizem o que escrever. A tela lê `limits`/`cost`/`required_inputs` (`use-video-models.ts:116-127`), o MCP lê custo e `is_primary` (`mcp-server/index.ts:~975-985`).
  - `video_models.notes`: texto humano por linha (SI:1166, 1171, 1200-1230; `hub-catalogo-ativar.sql:10-12`) — **ninguém lê** (quebrado #18).
  - `src/lib/model-notes.ts` (MN:10-55): uma frase por `model_id` para o portão de geração, hardcoded no front, fala de limite/custo, não de escrita.
  - `RECEITA_DO_ROTEIRO` e `RECEITA_DA_MONTAGEM` (RT:100-150): a única receita de verdade, entregue ao Claude em `roteiro_pedidos`/`video_pedidos` (`mcp-server/index.ts:1413, 1557`) — vale só para "avatar fala o roteiro"; não é por modelo (não distingue HeyGen IV/V, P-Video, OmniHuman) e não cobre cenas, Video Agent, Aleph, lipsync, troca de pessoa.
  - Regras de prompt de cena vivem como **prompt de sistema de LLM** (DC:61-98; SD:167-230) e como **código** (VP:654-721; RM:231-250; DA:843-866, 1387-1397, 3821-3823). Nenhuma é legível pela tela nem exposta ao conector.
  - `docs/catalogo-*.md` e `hub-motor-contratos.md` descrevem campos e limites, nunca "como escrever".
- Conclusão: para o hub do Samuel falta uma coluna/estrutura `video_models.recipe` (ou equivalente por `experience`) com: o que faz (1 frase), entrada que a pessoa dá, formato esperado do texto (idioma, tamanho, o que incluir/excluir, pausas), limites visíveis, e que o `mcp-server` devolva isso em `o_que_posso_fazer`/`video_criar` sem aceite e a tela leia a mesma fonte.

**(b) Quais funções já convertem "texto da pessoa" em "input do modelo", e para quais rotas isso NÃO existe?**
- Existem (ver §1): `generateDirectorPlan` (DC:245-275) → `unitPrompt`/`groupMotionPrompt`/keyframe (DA:843-866, 1336-1349, 1387-1397) para Diretor Higgsfield e Replicate; `buildSceneDirectorMessages` + `planDecoupage` + `buildKeyframePrompt`/`buildMotionPrompt` (SD; `decoupage.ts`; VP:654-721) para o Reel; `buildVisualPrompt` + `sceneInEnglish` (RM:231-250; DA:2506-2525) para Aleph/Kling v2v e edição de cena; `RECEITA_DO_ROTEIRO` via Claude da pessoa para o roteiro de avatar (RT:100-139); `falaPorExtenso` (`fala.ts`) antes de qualquer voz via `speak()`; `clipTtsText` (DC:231-242) para o TTS do Diretor; `prompt-assist` kinds video/scene (PA:14-31) nos dois campos onde o botão existe.
- Todas, exceto a receita do roteiro, usam `_shared/llm.ts` ou são código fixo (quebrado #20).
- **Não existe conversão** (texto cru → provedor): Video Agent (`prompt`), avatar por descrição e novo visual, descrição de voz, `motion_prompt` do avatar (nem campo), fala nova do Remake (apenas limite 600 e checagem de duração), `character_prompt` da troca de pessoa, texto do MiniMax TTS no Remake e no Reel (sem `falaPorExtenso`), prompt de trilha (`bedPrompt` é fixo, DC:214-221), e qualquer texto que chegue pelo MCP `video_criar` (`roteiro`/`ideia` passam direto, `mcp-criar.ts:50-87`).
